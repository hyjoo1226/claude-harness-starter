# review-loop

작성자 혼자 검증하면 처음 놓친 가정을 검증 단계에서도 다시 놓친다. 그래서 완료 보고 전에 맥락이 분리된 리뷰어의 PASS를 받는다.

## 절차

1. 검증 대상을 고정한다. 코드는 커밋 범위(`<base>..<head>`)나 diff, 문서는 파일 경로다. 기준 문서(요구사항, 구현설계의 해당 절, 제품 한 장)도 함께 정한다.
2. `code-reviewer` 에이전트를 호출한다. 프롬프트에는 대상, 기준 문서 경로, 회차만 넣는다. 수정 의도나 "이건 문제없다" 같은 작성자 설명, 작성자가 매긴 위험도 등급은 넣지 않는다. 리뷰어가 작성자의 가정에 끌려가지 않게 하기 위해서다.
3. 리뷰어 결과를 `_workspace/<과제명>/review-<회차>.md`에 저장한다.
4. 판정에 따라 분기한다.
   - PASS면 완료다. 사용자 보고에 "리뷰 N회차 PASS"와 "확인 필요" 항목을 함께 적는다.
   - REDO면 지적을 고친다. 동의하지 않는 지적은 근거를 `_workspace/<과제명>/review-<회차>-response.md`에 적는다. 그다음 같은 기준으로 다음 회차를 호출하면서 이전 REDO 목록을 넘긴다.
5. REDO는 최대 2회다(총 3회차). 3회차도 REDO면 더 고치지 말고, 남은 지적과 작성자 의견을 사용자에게 그대로 보고하고 판단을 받는다. 끝없는 수정 루프와 토큰 낭비를 막기 위해서다.

## 보조 검사

인증·권한, 결제, 개인정보가 닿는 변경이면 리뷰어 PASS 뒤에 `/security-review` 실행을 사용자에게 제안한다. 리뷰어를 대체하는 것이 아니라 관점을 하나 더하는 것이다.
